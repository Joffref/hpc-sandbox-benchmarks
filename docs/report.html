Run timeline

Every Blaxel run committed to the fork's dataset since 14 September, with the host the scheduler placed it on. Host type is read from the sandbox, not from the image, because the same image lands on different pools.

Status: complete means every planned cell validated; partial means the dataset kept the verified cells and recorded the failed ones as gaps. Runs before 17 September predate the Alpine port and used the Debian image on the EPYC pool.

What changed to get here, and what is still open

Fixed in the fork

  • Fork setup. Account-journal branches provisioned; Blaxel moved to benchmark-scoped admission so a shared dev workspace no longer blocks allocation.
  • Alpine port. apk package path, musl mise, apk Node 22, PTS from tarball, bash bootstrap, busybox-safe keepalive. Works on arm64 and x86_64.
  • Network resilience. apk retries and mirror fallback; DNS64/NAT64 fallback when the sandbox resolvers fail; each placement is probed for egress and dead ones are re-created, up to three times.
  • fio. Source tarball mirrored as a release asset and seeded into the PTS cache, since brick.kernel.dk is unreachable from the fleet.
  • Diagnostics. Every post-create step logs its state and architecture, so a failed cell names its cause in the job log.
  • Plan. realworld-openclaw is dropped for Blaxel at planning; its dependency ships no arm64-musl build.

Open

  • Placement is scheduler luck. The same image lands on ARM or Xeon depending on the hour. The SDK exposes region, subnet and egress gateway but no architecture knob; a way to pin the pool would make results comparable run to run.
  • ARM pool egress flaps. It failed on 17 Sep and again on 19 Sep before being repaired; the retry masks brief outages but not sustained ones.
  • Xeon pool is slow. Half the memory bandwidth and a fifth of the buffered disk throughput of EPYC; two runs agree. Worth knowing before quoting any "x86" number from it.
  • Long cells can lose their sandbox. The Mastra cell on 19 Sep 19:23 stopped responding after 80 minutes with a data-plane 404.
  • Not measurable on Alpine. realworld-openclaw (arm64-musl) and fast-cli (glibc-only Chrome).
